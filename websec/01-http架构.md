# Web 基础｜HTTP 客户端/服务器架构

任何 Web 安全的讨论都始于"请求是怎么发的"。这篇先把 HTTP 的客户端/服务器模型讲清楚。

## ① 是什么

**HTTP（超文本传输协议）** 是浏览器（客户端）与网站（服务器）之间通信的规矩：客户端发**请求**，服务器回**响应**。客户端通常是浏览器/App，服务器是托管网页与 API 的程序。
架构上还有**代理、网关、CDN** 等中间节点，它们会"看"或"改"你的流量——安全测试的切入点往往就在这些中间层。

## ② 为什么重要

- 不理解请求/响应模型，就不知道"数据从哪来、经谁手、到哪去"，后续所有攻击（中间人、缓存投毒、越权）都看不懂。
- 明确"谁是客户端、谁是服务器、中间有谁"，才能定位信任边界。

## ③ 核心概念拆解

- **请求组成**：方法 + URL + 协议版本 + 头（Headers）+ 可选 Body。类比"寄信：写收件人(URL)、贴邮票方式(方法)、信封备注(头)、信纸内容(Body)"。
- **响应组成**：状态码 + 头 + Body。状态码（200/301/404/500）告诉你结果。
- **无状态**：HTTP 本身不记"上一请求是谁"，会话靠 Cookie/Token 维持（见第 4 篇）。
- **中间人风险**：流量经过代理/WiFi/运营商，明文 HTTP 可被窃听篡改——所以才需要 HTTPS（第 5 篇）。

## ④ 常见误区

- **误区 1**：客户端=浏览器。App、爬虫、API 调用方都是"客户端"。
- **误区 2**：服务器只有一台。现实常是 CDN→网关→应用→数据库多层，每层都可能引入风险。
- **误区 3**：HTTP 自动安全。默认明文，安全靠额外机制（TLS、头、鉴权）。

## ⑤ 一句话小结

HTTP 是"客户端发请求、服务器回响应"的无状态模型；看清请求链路与中间节点，是理解一切 Web 安全的前提。
