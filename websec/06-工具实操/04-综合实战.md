# 综合：Burp + Postman 串一次完整测试

## 一句话定义
把前面工具串起来：**Postman 理清接口与鉴权，ZAP/Burp 广扫，Burp 手测绕过逻辑漏洞**，对照 WSTG 收口，出报告——形成"探查 → 扫描 → 手测 → 报告"完整闭环。

## 核心架构 / 工作原理

```mermaid
graph TD
  A[完整测试闭环] --> B[1. Postman 探查]
  B --> B1[导入/建集合，配 baseUrl/basePath]
  B --> B2[配环境变量/鉴权，登录拿 token 存环境]
  B --> B3[写 Tests 断言，理清"有哪些端点、参数是什么、怎么鉴权"]
  
  A --> C[2. ZAP 广扫]
  C --> C1[把 Postman/浏览器流量引到 ZAP 代理]
  C --> C2[Spider + Active Scan，产出初步告警清单]
  C3[被动扫描同步进行，补全被动规则发现]
  
  A --> D[3. Burp 手测深挖]
  D --> D1[可疑请求 Send to Repeater，重点验证]
  D2[越权: 改 id/user_id/object_id 看是否返回他人数据 (BOLA/IDOR, WSTG-ATHZ-04)]
  D3[注入: 参数塞 ' / $filter / <script> 看报错/差异 (WSTG-INPV-*)]
  D4[逻辑: 跳步骤/重复提交/改金额/并发 (WSTG-BUSL-*)]
  D5[会话/CSRF/CORS: Sequencer/Repeater/手工验证]
  
  A --> E[4. 对照 WSTG 收口]
  E --> E1[把发现映射 WSTG-XXX-NN，确保覆盖各大类]
  E2[严重度分级: Critical/High/Medium/Low/Info]
  E3[补遗漏类别: 如 4.2 配置、4.3 身份、4.8 错误、4.9 密码学]
  
  A --> F[5. 出报告]
  F --> F1[ZAP 导出 HTML/JSON + 手测证据截图/请求响应]
  F2[按 WSTG 报告要素整理: 严重度/复现步骤/影响/修复建议/复测]
  F3[交付: PDF/HTML/Confluence/Jira]
```

## 快速上手步骤

1. **Postman 探查 (15-30 分钟)**：
   - 见 [Postman 上手](01-postman上手.md) + [Postman 调 OAuth2](../../04-身份授权标准/06-postman调oauth2.md)
   - 建集合 → 配 `baseUrl` → 登录拿 `access_token` 存环境变量
   - 手建/导入所有端点 → 写 `Tests` 断言 → `Collection Runner` 跑通
   - 导出集合供 ZAP/Burp 用 (或直接用 Postman 代理)
2. **ZAP 广扫 (30-60 分钟)**：
   - 见 [ZAP 上手](03-zap上手.md)
   - 配置浏览器/Postman 代理指向 ZAP (`127.0.0.1:8080`)
   - 访问应用主流程 → ZAP 被动记录流量
   - `Quick Start` → `Automated Scan` → 目标 URL → Attack
   - 看 `Alerts` 高危/中危 → 导出初步报告
3. **Burp 手测 (1-4 小时，核心)**：
   - 见 [Burp 上手](02-burp上手.md) + [Burp 知识库](../../burp/burp.md)
   - Proxy HTTP history → 可疑请求右键 `Send to Repeater`
   - **重点验证清单**：
     | 类型 | WSTG ID | 验证动作 |
     |------|---------|----------|
     | IDOR/BOLA | ATHZ-04 | 改 `id`/`user_id`/`order_id` 看他人数据 |
     | 越权 | ATHZ-01/02/03 | 普通用户访问 `/admin/**`、`/api/users/{other}` |
     | SQLi/命令注入 | INPV-05/06 | 参数塞 `'` `;id` `$(id)` 看报错/差异/延时 |
     | XSS | INPV-01/CLNT-01 | 参数塞 `<script>alert(1)</script>` 看回显/执行 |
     | 逻辑绕过 | BUSL-* | 跳步/重放/改金额/并发/负数/超长 |
     | 认证缺陷 | ATHN-* | 枚举/弱锁定/绕过/会话固定/CSRF |
     | 会话/令牌 | SESS-* | Sequencer 测熵/ Cookie 属性/会话固定/CSRF Token |
4. **WSTG 对照收口 (30 分钟)**：
   - 打开 [WSTG 知识库](../../wstg/wstg.md) 12 大类逐项核对
   - 常漏类别：`4.2 配置`、`4.3 身份管理`、`4.8 错误处理`、`4.9 密码学`、`4.10 业务逻辑`、`4.11 客户端`、`4.12 API`
   - 补测漏项 → 更新发现清单
5. **出报告**：
   - ZAP `Report` → `Generate HTML Report` → 基础告录
   - 手测证据：Repeater 请求/响应截图、Payload、触发片段
   - 按模板整理：`标题/严重度/WSTG-ID/复现步骤/影响/证据/修复建议/复测`
   - 导出 PDF/HTML → 交付开发/管理层

## 踩坑避坑指南

| 场景 | 问题现象 | 原因 | 解决/最佳实践 |
|------|----------|------|---------------|
| 只跑扫描不手测 | 逻辑/业务/授权漏洞全漏 | 扫描器局限 | **自动扫描给"面"，手测给"深度"；二者缺一不可** |
| 手测无 Postman 探查 | 不知道端点/参数/鉴权，盲测低效 | 流程倒置 | **先 Postman 探查理清接口，再 Burp 手测** |
| 只测 Happy Path | 逆向/边界/异常分支全无覆盖 | 只验正向 | **每端点最少 3 例**：正向、逆向(400/401/404)、边界(空/超长/特殊字符) |
| 不对照 WSTG | 常漏配置/身份/错误/密码学/业务/客户端类 | 清单思维缺失 | **测试结束前必对照 WSTG 12 大类逐项核对** |
| 报告只列漏洞 | 无复现步骤/证据/修复建议，开发改不动 | 报告质量低 | **每个漏洞必含**：WSTG-ID、严重度、复现步骤(命令/点击路径)、请求响应证据、修复代码示例 |

## 替代方案对比

| 维度 | 本闭环 | 纯扫描器 | 纯人工渗透 | 红蓝对抗 |
|------|--------|----------|------------|----------|
| 覆盖度 | 高(工具+人工互补) | 仅技术漏洞面 | 深但面窄/慢 | 全真实攻击面 |
| 速度 | 中(数小时-天) | 快(分钟-小时) | 慢(天-周) | 慢(周-月) |
| 适合阶段 | 上线前/定期验收/赏金侦察 | CI/CD 门禁/日常巡检 | 高价值资产/合规审计 | 实战演练/应急响应 |
| 报告可落地性 | 高(证据+修复建议) | 中(需人工过滤) | 高 | 中(侧重攻击路径) |
