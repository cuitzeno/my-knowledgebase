# WSTG 实战｜客户端测试（4.11）

有些漏洞在"浏览器里"发作，服务器从没见过请求。WSTG 4.11 覆盖客户端侧的各类风险。

## ① 是什么

**客户端测试** 检查在用户浏览器中发生的漏洞：DOM XSS、JS 执行、HTML/CSS 注入、重定向、CORS、点击劫持、WebSockets、浏览器存储等。

## ② 为什么重要

- 客户端漏洞直接危害真实用户，且常绕过服务端防护。
- DOM 型问题数据只在客户端流动，传统扫描易漏，需浏览器内分析。

## ③ 核心概念拆解（对应 4.11.x）

- **DOM XSS（4.11.1）**：污染源（source）→ 危险接收器（sink）在客户端 JS 里，用 DOM Invader 追链路。
- **JS 执行 / HTML / CSS 注入（4.11.2–5）**：脚本/标记/样式被注入执行或渲染。
- **客户端 URL 重定向（4.11.4）**：`redirect=` 被改成恶意站钓鱼。
- **CORS（4.11.7）**：`Access-Control-Allow-Origin` 过度放行致跨域读数据。
- **点击劫持（4.11.9）**：缺 `X-Frame-Options`/CSP 被 iframe 覆盖。
- **WebSockets / Web Messaging（4.11.10/11）**：双向通道与跨文档消息是否校验来源。
- **浏览器存储（4.11.12）**：敏感数据是否落 `localStorage` 可被 JS 读。

## ④ 常见误区

- **误区 1**：服务端过滤了就安全。DOM XSS 数据可能只走客户端。
- **误区 2**：没弹窗=没 XSS。看 source→sink 链路比等弹窗更准。
- **误区 3**：CSP 万能。配置不当仍可绕过。

## ⑤ 一句话小结

客户端测试在浏览器内发作：DOM XSS、注入、重定向、CORS、点击劫持、WebSocket、存储——用浏览器内分析追 source→sink。
