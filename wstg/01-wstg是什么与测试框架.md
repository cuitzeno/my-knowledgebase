# WSTG 实战｜WSTG 是什么 & 安全测试框架

测 Web 安全容易"凭感觉乱点"。OWASP WSTG 给你一份公认的"测什么"清单。这篇先讲它是什么，以及它背后那套测试框架。

## ① 是什么

**WSTG（Web Security Testing Guide）** 是 OWASP 维护的开放标准，定义了 Web/API 应用安全测试的**方法论 + 检查清单**：每个测试项都写明"目标、怎么测、预期、结果判读"。
**测试框架（Testing Framework）** 指一套通用流程：明确范围 → 定测试目标 → 收集信息 → 逐项验证 → 分析数据 → 出报告。

## ② 为什么重要

- 没有清单，测试靠经验、易漏项；WSTG 把"该测的"固化成可复用的目录。
- 它是行业沟通语言：客户、审计、扫描器都引用它，报告里写"依 WSTG 4.1.x"对方就懂。
- 框架保证"先信息收集、后攻击、最后报告"，而不是一上来就扫。

## ③ 核心概念拆解

- **四大阶段**：
  - *范围与目标*：确认授权边界、测试目标（功能/合规）。
  - *信息收集*（被动+主动）：摸清资产面。
  - *逐项测试*：按 4.1–4.12 各大类走查。
  - *分析与报告*：汇总发现、定风险、给修复建议。
- **测试项结构（ID 如 4.4.1）**：每个都含 Summary（为何测）、Test Objectives（目标）、Test Methods（怎么做）、Remediation（怎么修）。
- **与工具的关系**：WSTG 定义"测什么"，Burp/ZAP 是实现"怎么测"的工具——前者是地图，后者是车。

## ④ 常见误区

- **误区 1**：WSTG 是一本书，照着念就行。错，它是活的检查清单，要结合目标裁剪。
- **误区 2**：只跑自动扫描对照 WSTG ID。扫描器只能覆盖部分，手测项（逻辑/业务）仍需人工。
- **误区 3**：框架=线性流程。实际常迭代：测中发现新资产，回去做信息收集。

## ⑤ 一句话小结

WSTG 是 Web 安全测试的"标准清单"，框架=范围→收集→逐项测→报告；它与工具互补，告诉你该测什么。
