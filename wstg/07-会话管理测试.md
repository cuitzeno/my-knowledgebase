# WSTG 实战｜会话管理测试（4.6）

登录后靠"会话"维持身份，会话一旦被预测或劫持，登录再强也没用。WSTG 4.6 测整套会话生命周期。

## ① 是什么

**会话管理测试** 验证从登录签发、持续维持到销毁的全过程是否安全：令牌是否随机、Cookie 是否严谨、能否被固定/劫持、登出与超时是否可靠。

**WSTG 类别码：`SESS`**

## ② 为什么重要

- 会话令牌可预测 = 攻击者可"算"出别人会话直接登录。
- 无 HttpOnly/Secure、会话不刷新、登出不失效，都是被劫持的高危点。

## ③ 核心概念拆解（对应 4.6.x）

- **会话模式（4.6.1）**：检查令牌生成算法、是否可预测、是否绑定必要上下文。
- **Cookie 属性（4.6.2）**：`HttpOnly`（防 JS 读）、`Secure`（仅 HTTPS）、`SameSite`（抗 CSRF）、`Path/Domain` 是否过宽。
- **会话固定（4.6.3）**：登录前后会话 ID 是否变化，未变则危险。
- **暴露的会话变量（4.6.4）**：令牌是否出现在 URL/日志。
- **CSRF（4.6.5）**：关键请求是否带不可预测 token。
- **登出/超时/混淆/劫持（4.6.6–9）**：登出是否真销毁、超时是否合理、是否可被"会话困惑"或劫持。

## ④ 常见误区

- **误区 1**：令牌长=随机。自增/时间戳虽长但可预测。
- **误区 2**：有 HTTPS 就够。HttpOnly/SameSite 仍关键。
- **误区 3**：登出按钮点了就安全。要确认服务端会话真正失效。

## ⑤ 一句话小结

会话测试覆盖"签发→维持→销毁"：令牌随机性、Cookie 属性、固定/暴露/CSRF、登出与超时——任何断点都能被劫持。
