# WSTG 实战｜API 测试与报告（4.12 + 5）

现代应用大量用 API，WSTG v4.2 专门补了 API 测试大类；测完还要把发现变成可交付的报告。这篇收尾这两块。

## ① 是什么

- **API 测试（4.12）**：把前面各大类的思路应用到 REST/GraphQL/SOAP 等接口——参数、鉴权、速率、对象级授权（类比 IDOR）。
- **报告（5）**：把测试结果整理成带风险评级、复现步骤、修复建议的交付物。

## ② 为什么重要

- API 常是"无界面"的高权限入口，绕过了传统页面的防护。
- 不写报告，测试价值归零；报告不清，开发不知从哪修起。

## ③ 核心概念拆解

- **GraphQL 测试（4.12.1）**：introspection 是否暴露全 schema；深嵌套/批量查询能否打 DoS；字段级越权。
- **API 通用检查**：鉴权（token 泄露/过期）、速率限制、对象级授权（改 ID 越权）、批量端点泄露。
- **报告要素（5）**：
  - *摘要*：范围、方法、总体风险。
  - *发现列表*：每项的严重度、位置（URL/参数）、复现步骤、证据、影响、修复建议。
  - *风险定级*：结合可利用性与影响，用统一标准（如 OWASP Risk Rating）。

## ④ 常见误区

- **误区 1**：API 有鉴权就安全。对象级越权（BOLA）是 API 头号风险。
- **误区 2**：GraphQL 关了 introspection 就安全。字段越权仍在。
- **误区 3**：报告只贴"有漏洞"。要带复现与修复优先级。

## ⑤ 一句话小结

API 测试把大类思路落到接口（重点查对象级授权与 GraphQL），报告把发现变成"可修的交付物"——这是 WSTG 的终点。
