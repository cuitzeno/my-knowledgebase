# Postman 实战｜安装、配置与界面导览

装好 Postman 后一头雾水？这篇先带你把环境搭起来，再认一遍界面上最常用的几块区域，后面发请求、写脚本就不迷路了。

## ① 是什么

Postman 有桌面客户端（Windows / macOS / Linux）和网页版。日常开发用桌面版更顺手，因为能直接调用本地服务、保存历史、离线工作。

## ② 为什么重要

- 不先建好"工作区（Workspace）"，团队的请求、集合、环境就会散落各处，协作时找不到东西。
- 弄清界面分区，才能知道"请求写在哪、响应看哪、脚本点哪"，否则一上手就卡在按钮上。

## ③ 核心概念拆解

- **安装与登录**：去官网下载安装包 → 启动 → 登录账号（免费版足够个人使用）。登录后才能同步集合、使用协作与云监控。
- **Workspace（工作区）**：相当于一个项目文件夹。建议一个团队/一个 API 项目建一个 Workspace，把相关集合、环境、文档都放进去。
- **界面四大区**：
  - *侧边栏*：管理集合（Collections）、环境（Environments）、Flows、历史记录。
  - *请求构建区*：填 URL、选方法（GET/POST…）、设参数、Header、Body、写脚本。
  - *响应查看区*：看状态码、耗时、返回体、Header、测试结果。
  - *顶部栏*：切换工作区、搜索、新建、运行集合（Runner）。

## ④ 常见误区

- **误区 1**：不登录就用。能发请求，但集合不会云同步，换电脑就丢了。
- **误区 2**：把所有接口堆在默认工作区。项目一多就乱，应按项目分 Workspace。
- **误区 3**：只在网页版用。网页版对本地服务的 CORS、代理支持不如桌面版稳。

## ⑤ 一句话小结

先建 Workspace 再登录同步，认准"侧边栏 / 请求区 / 响应区 / 顶栏"四块，Postman 的骨架就清楚了。
