# 安装、配置与界面导览

## 一句话定义
Postman 提供 **桌面客户端**(Win/macOS/Linux)与 **Web 版**；桌面版支持本地服务调用、离线工作、代理抓包、更稳定的 CORS 处理，是日常开发首选。

## 核心架构 / 工作原理

```mermaid
graph TD
  A[Postman 运行模式] --> B[桌面客户端 Desktop App]
  B --> B1[Electron + Node.js]
  B --> B2[原生代理/证书管理]
  B --> B3[本地文件系统访问]
  B --> B4[离线模式/历史记录本地存]
  
  A --> C[Web 版 Postman Web]
  C --> C1[浏览器沙箱受限]
  C --> C2[需 Postman Agent 访问本地]
  C --> C3[CORS 受浏览器策略限制]
  C --> C4[云同步优先]
  
  D[核心数据模型] --> D1[Workspace 工作区: 项目容器]
  D --> D2[Collection 集合: 请求分组+测试脚本]
  D --> D3[Environment 环境: 变量键值对(dev/stage/prod)]
  D --> D4[API: OpenAPI 契约+版本+Mock+文档]
  D --> D5[Monitor: 定时跑集合的调度配置]
  D --> D6[Flows: 可视化请求编排]
```

| 组件 | 作用 | 典型操作 |
|------|------|----------|
| **Workspace** | 隔离项目/团队上下文 | 一个 API 项目 = 一个 Workspace；Personal/Team/Private 三种可见性 |
| **Collection** | 请求的文件夹+测试脚本 | 建文件夹按模块/版本分组；文件夹级 Pre-request/Test Scripts 复用 |
| **Environment** | 环境变量集(dev/stage/prod) | `{{base_url}}` `{{api_key}}` `{{user_id}}`；Current/Initial value 区分运行时/初始值 |
| **Variables** | 变量作用域链 | Global → Collection → Environment → Data → Local；优先级由低到高覆盖 |
| **Settings** | 代理/证书/同步/主题/快捷键 | Proxy → Custom Proxy Configuration(抓包用)；Certificates → Client Certificates(双向 TLS) |

## 快速上手步骤

1. **下载安装**：
   - 官网 <https://www.postman.com/downloads/> → 下载对应平台安装包 → 安装
   - 首启动 → 登录/注册账号(免费版足够个人/小团队) → 云同步开启
2. **建 Workspace**：
   - 左上角 Workspace 下拉 → Create Workspace → 命名(如 `MyAPI-Project`) → Team visibility → Create
3. **认界面四大区**：
   - **侧边栏**：Collections / APIs / Environments / Mock Servers / Monitors / Flows / History
   - **请求构建区**：Method 下拉、URL 输入、Params/Authorization/Headers/Body/Pre-req/Scripts 标签
   - **响应查看区**：Status/Time/Size、Body(Pretty/Raw/Preview/Visualize)、Headers、Test Results、Cookies
   - **顶部栏**：Workspace 切换、搜索、New、Import、Runner、Sync 状态、账号菜单
4. **配置代理抓包(可选)**：
   - Settings → Proxy → Add Custom Proxy Configuration → `127.0.0.1:8080` → 做 Burp/ZAP 上游代理
   - 或用 Postman 自带 Proxy(Interceptor 扩展)抓浏览器流量
5. **配置双向 TLS(可选)**：
   - Settings → Certificates → Add Client Certificate → Host/Port + PFX/CRT+Key + Passphrase

```bash
# CLI 验证安装(装完 Postman CLI 后)
postman --version
# 或用内置 Newman
newman --version
```

## 踩坑避坑指南

| 场景 | 问题现象 | 原因 | 解决/最佳实践 |
|------|----------|------|---------------|
| 不登录直接用 | 集合只存在本地、换机器丢失、无法协作 | 未关联账号 | **首启动即登录**；免费版同步无限制 Personal Workspace |
| 全部请求塞默认 Workspace | 项目多后找不到、权限混乱 | 无隔离规范 | **一项目一 Workspace**；Team Workspace 给成员角色(Viewer/Editor/Admin) |
| Web 版调本地 `localhost` 失败 | CORS 报错/连接拒绝 | 浏览器沙箱限制 | **装 Postman Desktop Agent** 或直接用桌面版 |
| 变量不生效/值不对 | `{{var}}` 没替换/值旧 | 作用域优先级不懂 | 理解变量链：Local(临时) > Data(CSV) > Environment > Collection > Global；用 `pm.variables.get()` 调试 |
| 证书/代理配置乱 | 抓不到 HTTPS/双向 TLS 失败 | 配置入口深 | Settings → Proxy/Certificates 统一配置；代理模式选"System Proxy"或"Custom" |

## 替代方案对比

| 维度 | Postman Desktop | Postman Web | Insomnia | HTTPie / curl |
|------|-----------------|-------------|----------|---------------|
| 本地服务调用 | ✅ 原生 | ⚠️ 需 Agent | ✅ 原生 | ✅ 原生 |
| 离线工作 | ✅ 完全 | ❌ 需网 | ✅ 完全 | ✅ 完全 |
| 代理抓包/证书 | ✅ 完善 | ❌ 无 | ⚠️ 基础 | ❌ 无 |
| 团队协作/同步 | ✅ 云同步 | ✅ 云优先 | ✅ 同步(付费) | ❌ 手动 |
| 界面可视化 | ✅ 丰富 | ✅ 丰富 | ✅ 简洁 | ❌ CLI |
| 资源占用 | 较高(Electron) | 低(浏览器) | 中等 | 极低 |
