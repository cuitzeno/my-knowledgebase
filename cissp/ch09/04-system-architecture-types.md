# Ch9-04 系统架构类型：客户端/服务器、分布式、高性能、实时系统

> 所属域：Domain 3 Security Architecture and Engineering
> 对应原书：Chapter 9 — Client-Based / Server-Based / Distributed / HPC / Real-Time Systems（及 ICS 概要）

## ① 一句话秒懂
不同系统架构有不同攻击面：**客户端**重在终端防护，**服务器**重在可用与加固，**分布式/网格**重在单点故障与中心控制，**工业控制系统（ICS）**重在隔离与补丁滞后，**实时系统（RTOS）**重在资源受限下的最小安全。

## ② 生活类比
服务器像中央厨房（一处出问题全场没饭吃，须冗余）；分布式像众包（节点多但调度难）；ICS 像电厂控制室（原本不联网、设计时就没考虑安全，反而成为弱点）；RTOS 像心脏起搏器（必须准时，没余力搞复杂安全）。

## ③ 核心概念（大白话 + 原书定义）

**客户端系统（Client-Based）**
用户直接交互的端点（PC、笔记本、瘦客户机）。安全重点：端点防护、补丁、全盘加密、防恶意代码、访问控制。

**服务器系统（Server-Based）**
提供共享服务的核心系统。安全重点：加固（hardening）、高可用、备份、严格访问控制、监控。宕机影响面广。

**分布式系统（Distributed Systems）**
计算/数据分散在多个节点协同工作。
- **Grid computing（网格计算）**：中央服务器管理任务包、整合结果；中心过载/离线可致整体失败，且中心被控可指挥成员作恶。
- **Peer-to-Peer（P2P，点对点）**：无中央管理，实时共享任务；风险：助长盗版、可被窃听、缺乏管控、吞带宽。

**高性能计算（HPC）**
超强算力集群，用于科研/大模型等。安全重点：资源调度安全、隔离多租户、高速网络防护。

**实时操作系统（RTOS）**
以最小延迟处理到达的数据，常存于 ROM，分：
- 硬实时（hard real-time）：延迟须消除/最小化（如自动驾驶，关乎安全）。
- 软实时（soft real-time）：可容忍适度延迟（多数消费电子）。
- 事件驱动（按优先级切换）vs 时间共享（按时钟中断切换）。
安全顾虑：单用途、定制/专有代码可能含未知漏洞；易被伪造数据/请求拖垮；部署时应做隔离与通信监控。

**工业控制系统（ICS / OT）**
控制工业流程与机器的计算机管理设备，又名运营技术（OT）/工业 IoT（IIoT）。形式：
- **PLC（可编程逻辑控制器）**：单用途数字计算机，控单台设备（如一个变压器）。
- **DCS（分布式控制系统）**：单地点内分布式控制，状态驱动（state-driven），适合有限规模（如电站）。
- **SCADA（数据采集与监控系统）**：事件驱动（event-driven），带 HMI 人机界面，适合大地理范围（如电网）。DCS 控流程、SCADA 收数据——PLC 控单点、DCS 管一站、SCADA 管全网。
- **Modbus**：1979 年 Modicon 制定的工业通信事实标准协议，促互操作。
历史：ICS 因静态设计、极少人机接口，过去几乎没安全；Stuxnet 首次将 rootkit 送入核设施 SCADA 是著名案例。至今许多 ICS/SCADA 仍防护薄弱、更新稀少。

## ④ 真实案例
- **Stuxnet**：通过 USB 与网络漏洞攻入伊朗核设施 SCADA，篡改离心机——ICS 隔离不足的典型。
- 电网 SCADA 被控可致大面积停电（如 2015 乌克兰电网事件）。
- 起搏器等医疗设备用 RTOS，固件漏洞可能直接威胁生命。

## ⑤ 考试怎么考
- ICS 三件套区别：PLC（单设备）/ DCS（状态驱动、局部）/ SCADA（事件驱动、广域）。
- DCS 是 state-driven，SCADA 是 event-driven。
- RTOS 硬实时 vs 软实时；事件驱动 vs 时间共享。
- P2P 无中央管控的风险；网格计算的中心节点风险。
- ICS 安全薄弱的根因：静态设计+历史无安全+补丁滞后。

## ⑥ 记忆口诀
- PLC 控一点，DCS 管一站，SCADA 管全网；DCS 状态驱，SCADA 事件驱。
- 实时分硬软：硬不可延迟（安全），软可稍等（消费）。
- 网格有中心，P2P 无中央；ICS 本无安全，Stuxnet 是警钟。
